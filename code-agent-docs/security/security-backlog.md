# Security backlog

| Field | Value |
|---|---|
| Version | 1.0 (2026-10-01, session S007, plan change request #10) |
| Purpose | Findings that do not block a stage under the owner's decision D1: **Tier 2** Medium, Low, and informational findings, and **Tier 1** Low and informational findings ([security policy](../../docs/security/security-policy.md), 7.1) |
| Rules | Each item has a severity, an owner, and a target release. The backlog is reviewed at every stage's final review (rule R15). A Medium item older than two releases is raised to the owner. Critical and High findings never go here: they block the stage (Tier 1 and Tier 2). A Tier 1 Medium finding goes here only with the owner's written risk acceptance, recorded in the [risk register](risk-register.md). |
| Not here | Details of vulnerabilities in **released** versions before their fix: those stay in private GitHub security advisories ([vulnerability management](../../docs/security/vulnerability-management.md)). |
